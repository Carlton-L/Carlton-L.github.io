# carlton-astro — Claude Guidelines

Portfolio site for carlton.dev. Astro 6 + React islands + Tailwind 4, static output, deploys to GitHub Pages (**replaces** the Carlton-L.github.io repo contents entirely).

## Design system: "THE PATCH"

The site is a live dataflow network (TouchDesigner-derived grammar). **Read `../design/DIRECTION_PATCH.md` before any UI work.** Core rules:

- Content blocks are **operators** (`src/components/Operator.astro`): typed header (VIEW / TXT / DATA / SYS), in/out ports, draggable in network mode.
- Navigation between ideas = **cables** (bezier wires with flowing signal pulses, drawn into an svg.wires layer; see homepage inline script).
- The dither background is **generated by a visible SYS operator chain** with an exposed DENSITY parameter — the site explains itself.
- **Two modes**: NETWORK (spatial patch) and PERFORM (`body.perform` — clean stacked reading view). Toggle = P key / navbar button; perform is the default on mobile and `prefers-reduced-motion`. EVERY new component must work in both modes.
- Footer is a **playbar** (timeline strip); nav is the **PatchBar** (network path readout + mode toggle + cook status).
- Type: Archivo (900, display, uppercase) + Inter (body) + JetBrains Mono (all UI/labels). Signal accent `--signal: #3dff88` — used for cables, live states, links; not a costume.
- Viewer interiors (demos) use each **product's real visual language**, scoped inside the VIEW operator: Futurescaper = ink-on-paper `--paper`/`--ink`, amber `--amber`, Wong STEEPLE palette (`--steep-*`). Tokens already in `src/styles/tokens.css`.
- Case studies are **networks**: INPUT (problem) → PROCESS (decision nodes) → VIEW (live demo) → OUT (outcome/next). Shared spine, bespoke topology + viewer per project.

## Conventions

- Design tokens: `src/styles/tokens.css` (token NAMES are stable; Tailwind maps them in `tailwind.config.mjs`).
- Content: `src/data/content.js` (single source for projects/case-study copy — copy is fact-checked; do not embellish roles or numbers. NEVER name Futurity clients).
- Prefer zero-JS Astro; use inline vanilla `<script is:inline data-astro-rerun>` for patch behaviors; React islands only for heavy demos (`client:visible`, or `client:only="react"` + poster for WebGL).
- SEO: every page needs the JSON-LD helpers from `src/lib/seo.js`; keep unique titles/descriptions.
- Astro quirk: variables used by `getStaticPaths` must be defined INSIDE it.
- Performance budget: homepage ships ~zero framework JS; demo islands ≤300KB gz; never scroll-jack; respect reduced motion.

## Building in the Cowork sandbox

The mounted repo's `.vite`/`.astro`/`dist` caches are NOT writable from the Linux sandbox. To verify builds: copy the project (excluding node_modules/.astro/dist) to /tmp, `npm install --prefer-offline`, `npx astro build` there. `astro.config.sandbox.mjs` exists for this; safe to ignore locally.
